# together. — онлайн-кинотеатр для совместного просмотра

Сайт, в котором два человека (например, один в Польше, другой в Казахстане) могут зайти в одну комнату по ссылке, одновременно смотреть YouTube и видео, ставить на паузу, перематывать и переписываться. Регистрация не нужна.

## Возможности

- **YouTube:** вставь ссылку на обычное видео, Shorts или трансляцию. Пауза, воспроизведение и перемотка синхронизируются между подключёнными зрителями.
- **Прямые ссылки:** MP4, WebM, OGG, HLS (`.m3u8`). Файл должен быть доступен браузерам обоих участников.
- **Фильмы на других сайтах:** кнопка **«Трансляция»** позволяет показать вкладку Chrome/Edge другому человеку вместе со звуком через WebRTC.
- **Приглашение:** нажми **«Копировать ссылку»**, отправь её другу; имя можно ввести без регистрации.
- **Общий чат, список участников, полноэкранный режим, мобильная версия.**

В комнату помещается до восьми человек. Комната создаётся по случайному коду. Сообщения и состояние видео хранятся **только в памяти сервера**, без аккаунтов и базы данных.

## Как сделать сайт доступным по интернету — без терминала

Нужны бесплатные аккаунты GitHub и Render.

1. Скачай ZIP и **распакуй** его. Внутри папки `together-watch` находятся `server.js`, `package.json`, `render.yaml`, папка `public` и другие файлы.
2. На [github.com/new](https://github.com/new) создай новый репозиторий, например `my-watch-room` (можно Private). В репозитории нажми **Add file → Upload files**, перетащи **содержимое** распакованной папки (`server.js`, `package.json`, папки `public`, `test` и т. д.). Подтверди кнопкой **Commit changes**. Важно, чтобы `package.json` лежал в корне репозитория, а не во вложенной папке.
3. На [dashboard.render.com](https://dashboard.render.com) открой **New → Web Service**, подключи свой GitHub и выбери репозиторий.
4. Заполни параметры: **Language/Runtime: Node**, **Build Command: `npm install`**, **Start Command: `npm start`**, **Instance Type: Free**. Render может автоматически прочитать `render.yaml` через **New → Blueprint** — это альтернативный способ. Для обычного Web Service параметров выше достаточно.
5. После успешного деплоя Render выдаст адрес вида `https://my-watch-room.onrender.com`. **Это твой реальный сайт.** Открой его на своём компьютере, введи имя, нажми «Создать комнату» и скопируй приглашение. Подруга заходит по той же ссылке из Казахстана.

Для бесплатного хостинга Render обычна пауза после 15 минут бездействия — при следующем открытии прогрев может занять около минуты. Если Render перезапустится, история чата и текущее видео могут сброситься.

Важно: **статический хостинг GitHub Pages не подходит** — для синхронизации и чата необходим работающий сервер Node.js.

## Как запустить на компьютере (Windows, macOS или Linux)

Требуется Node.js 20 или новее.

```bash
npm install
npm start
```

Открой `http://localhost:3000`. Также можно запустить `start-windows.bat` в Windows. **Локальный адрес доступен только на твоём устройстве**, пока сайт не опубликован в интернете.

## Как смотреть фильмы с сайтов

1. Открой фильм в **Google Chrome** или **Microsoft Edge** на компьютере.
2. В комнате together. нажми **«Трансляция»**.
3. Выбери вкладку с фильмом и включи опцию **«Поделиться аудио вкладки»**.
4. Нажми «Поделиться». Другу нужно разрешить воспроизведение, если браузер об этом попросит.

**Ограничения:** обычный адрес страницы фильма часто не является прямой ссылкой на видеопоток — такую страницу нельзя просто вставить в видеоплеер. DRM-защита платных платформ может блокировать запись экрана/звук и показывать чёрный экран: сайт не пытается обходить ограничения. Отдельные видео YouTube нельзя встроить по решению автора или платформы; возрастные и региональные ограничения также действуют.

## Если трансляция не соединяется между разными странами или операторами

Для прямого WebRTC-соединения приложение по умолчанию использует общедоступные STUN-серверы Google. В некоторых сетях, особенно за строгим NAT или мобильными провайдерами, требуется **TURN-сервер**. Это нормально: код не может гарантировать соединение через любые провайдеры без TURN.

Арендуй или настрой TURN у провайдера (например, coturn / управляемый TURN) и добавь в Render → Web Service → **Environment** переменную `ICE_SERVERS_JSON`. Пример (замени `TURN_HOST`, имя и пароль своими):

```json
[{"urls":"stun:stun.l.google.com:19302"},{"urls":"turn:TURN_HOST:3478?transport=udp","username":"TURN_USERNAME","credential":"TURN_PASSWORD"},{"urls":"turns:TURN_HOST:5349?transport=tcp","username":"TURN_USERNAME","credential":"TURN_PASSWORD"}]
```

Не записывай действующие пароли в GitHub. Если использовать TURN, аудио/видео может идти через него, и обычно это создаёт трафик, который оплачивается отдельно провайдеру TURN.

## Тестирование и безопасность

```bash
npm test
```

Проверяются создание комнат, валидация ссылок, вход двух участников, чат, пауза и перемотка, ограничения доступа к сигналам экрана и лимит участников. Эти тесты используют имитацию Socket.IO, поэтому **не заменяют полную проверку с двух реальных браузеров** после деплоя.

Комнаты не имеют пароля: **любой, кому ты отправишь ссылку, сможет войти**. Не выкладывай приглашение публично. Чат очищается при перезапуске сервера; сообщения не шифруются на уровне приложения, а транспорт защищается HTTPS/WSS при хостинге на Render. Если будешь делать публичный сервис на множество людей, понадобятся дополнительные ограничения против спама и злоупотреблений.

## Структура проекта

- `server.js` — Express, Socket.IO, комнаты, синхронизация, чат, WebRTC-сигналинг.
- `public/index.html` — разметка.
- `public/styles.css` — адаптивный дизайн.
- `public/app.js` — клиентская логика, YouTube Iframe API, HLS, WebRTC.
- `render.yaml` — параметры бесплатного Web Service на Render.
- `test/server.test.js` — серверные логические тесты.

Лицензия: проект для личного использования; он не содержит или не распространяет фильмы и не обходит защиту видеосервисов.
